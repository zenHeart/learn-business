# ch2 验证

> 验证的定义只有一个：有人**付出代价**表达意愿。点赞、问卷、"挺好的"，都不算。

## 这个阶段真正的问题

工程师创业的默认路径是"先做出来再说"——把最强的能力（做）用在最早的阶段，而验证阶段恰恰**不该做**。验证阶段的产出物不是产品，是**付费意愿的证据**。

三种证据强度，从弱到强：

| 强度 | 证据 | 置信度 |
|---|---|---|
| 弱 | 问卷说"会买"、点赞、加群 | ≈0（社会期许偏差） |
| 中 | 留邮箱进等待名单（Waitlist） | 低-中（免费动作） |
| **强** | **预售付全款 / 付定金 / 签 LOI** | 高（真金白银） |

Indie Hackers 社区共识的验证路径：**落地页 + 预售**——一个页面讲清"帮谁解决什么、多少钱"，挂支付按钮。有人付钱就做，没人付钱就换。你的成本是一天，不是三个月。

## 落地页验证的操作

最小验证落地页四要素：

1. **一句话定位**（ch1 的产物）
2. **痛点共鸣**：用户原话（从 ch1 收集的吐槽里摘）
3. **价格锚**：写明预期价格区间——免费收集的"兴趣"和标价后的"兴趣"是两个物种
4. **转化动作**：预售按钮 / 等待名单。按钮点不动 = 验证失败，这本身就是结果

流量来源不用买：目标用户聚集的社群、相关话题下的一篇深度内容、10 个精准用户的私下访谈。

### 数字参考

- 全行业落地页转化率中位 **6.6%**（Unbounce 2024，4.1 万页样本；含点击/表单，不等于付费）；另一口径（WordStream）行业均值 **2.35%**、Top 10% **11.45%+**——两个口径并陈，差异来自样本与转化定义（详见附录）
- 等待名单 → 付费的典型损耗一个数量级；**别把名单数当收入预期**

## 快速验证的时间盒

2026 年被反复验证的节奏（中文一手访谈 + Indie Hackers 共识）：

```
想法 → 落地页/预售验证：1-3 天
验证通过 → MVP 上线：2 周（AI 辅助开发的中位时长）
上线 → 首个付费用户：数天-数月（差异最大的阶段，见 ch5/ch6）
方向不对 → 换下一个：数周内决策，不恋战
```

Marc Lou 模式的本质就是这个时间盒的工业化：21 个产品 12 个活——**用数量吃掉单点的不确定性**，前提是每个验证都便宜（他大多数产品启动成本 < $500）。

中文访谈里同样的表达："25 分钟能做出 demo 的事，就别拖到 25 天""先做 demo，能跑就上线"。

## 坑与证伪

| 流行做法 | 问题 |
|---|---|
| MVP 打磨 3 个月再上线 | 验证阶段最大的浪费。2 周做不出的 MVP 要么范围太大，要么该直接卖服务人工交付（ch3） |
| 免费内测收集反馈 | 免费用户给的是"兴趣反馈"，付费用户给的是"价值反馈"。样本要小而付费，不要大而免费 |
| "等我把技术再学深一点" | 技术深度不是验证的瓶颈（AI 已补齐执行），需求和渠道才是。这个借口背后通常是怕被拒绝 |
| 问卷调研 N=100 | 问卷只能排除明显不行的方向，不能证明行。付款是唯一的高置信信号 |
