# ch12 交付与自动化

> **本章目标**：理解 AI 时代的成本结构革命与"巴士测试"；掌握 2026 单兵工具栈；明确什么自动化、什么不自动化。这是把"只有你能做"的部分释放出来的章节——也是 ch13 财务的支撑。

## 真实场景

一位独立开发者把"产品按时上线"挂在嘴边两年，每天亲自写代码、亲自回复客户、亲自做营销——结果每天工作 14 小时，月入 3 万；他大厂同期的同事，每天 8 小时月入 4 万。**他没有用错能力，他只是没有用对自动化**——把"只有你能做的判断"和"谁都能做的执行"混淆，结果用稀缺资源去做不稀缺的事。

## 成本结构的革命

| 项目 | 传统 5-15 人团队 | 一人 + AI | 降幅 |
|---|---|---|---|
| 年运营成本 | 约 $22.5 万 | 约 $1.8 万 | **-92%** |
| 开发 | 5 人 | 1 人 + AI Coding | -80% |
| 设计 | 全职 | 1 人 + AI 生图 | -90% |
| 内容 | 3 人 | 1 人 + LLM | -85% |
| 客服 | 5 人 | Agent 机器人 | -95% |

真实创业者自报的 AI 承担比例：美术 70%（弹幕游戏完整链路）、重复性工作 80%（跨境电商）、数据/报告 80%。**剩下的 20-30% 是判断、框架设计与客户沟通**——这是 ch01 说的"行业认知所在"，也是你无法外包的稀缺能力。

## 巴士测试：自动化的验收标准

Levels 在《MAKE》给的标准：**你被公交车撞了，产品还能正常运行多久？**

- 最低门槛：**周末测试**（两天不管不崩）
- 检查项：付款→交付（ch10 自动闭环）；常见问题自助（FAQ/知识库）；故障时的降级路径；月度账单自动对账
- 过不了的业务 = 你买了一份不能请假的工作，不是资产（对照 ch13 的资产定义）

## 单兵工具栈（2026 事实标准）

被社区固化的组合（月成本 $20-50 起步）：

```
开发：Next.js + TypeScript（全栈统一，生态最完整）
UI：Tailwind + shadcn/ui（组件够用、能复用）
数据：Supabase（自带 Auth + Postgres，免费层够起步）
部署：Vercel（Git push 自动）
收款：Stripe 海外 / 微信/支付宝 国内
AI：Cursor / Claude Code / DeepSeek / 豆包（按需）
异步协作：Linear（轻量）+ Notion（文档）+ Discord/Slack（社群）
邮件：ConvertKit / Beehiiv
分析：PostHog（产品）+ Plausible（站点）
```

选择原则：**最短路径 + 最低维护**。每个新工具都加订阅成本和失效点。判断标准：**工具替代的工时 > 维护它的工时**才引入。

## 什么不自动化

按场景区分：

| 自动化 | 不自动化 |
|---|---|
| 重复性执行（生成、测试、部署、报表） | 关键客户关系（首单欢迎、流失挽回、大客户投诉） |
| 自动交付（付款→开通） | 产品方向决策（数据回收可自动化，决策不可） |
| 客服 FAQ 自助 | 内容的人格部分（受众跟随的是你——ch08） |
| 邮件序列 | 复杂的销售对话（ch10） |

**判据一句话：** 用你的稀缺判断力做该做的事，其他交给系统。一周里"只有你能做"的事低于 50%，说明自动化布局合理；高于 80%，说明你被困住了。

## 自动化的阶段化路径

不是一次到位：

```
第 0 步：手动跑通全流程（哪怕用 Notion + Excel）
第 1 步：把最痛的两段脚本化（自动交付、邮件回复模板）
第 2 步：扩到日常 80% 的重复操作
第 3 步：把"我定期要做但没自动化"全清出去
```

跳过前 1 步的自动化 = 给没跑通的流程加复杂度，常见失败模式：**手动都没跑过的流程没有自动化资格**——你不知道哪些是真实痛点哪些是花架子。

## 成本清单（写下来才有边界）

月度三类支出，记账要做到能 30 秒回答：

```
AI 工具订阅：Cursor $20 + Claude Code $20 + … = X
基础设施：Vercel/Supabase/Stripe = Y
外包：客服代理/剪辑/初稿 = Z
```

可接受边界：**月度运营成本 ≤ 当月 MRR 的 30%**。否则结构问题不是获客不够，是基础设施选择过重（ch11 毛利率应>80% 的数字产品，运营成本超 30% 就是反向信号）。

## 坑与证伪

| 坑 | 核查 |
|---|---|
| 全自动躺赚 | "被动收入"叙事被反复打脸。MRR 中位 $145-500 的现实里，自动化降的是交付成本，**获客与信任没有被动版** |
| 工具链越全越好 | 每个工具 = 订阅 + 失效点 + 学习成本。判断标准简单：替代工时 > 维护工时 |
| 把 AI 当技术合伙人 | AI 是执行放大器：放大正确判断，也放大错误判断（ch01 ch14）。行业老手 + AI 是杠杆；新手 + AI 是加速犯错 |
| 自动化一次到位 | 渐进路径：手动跑通 → 痛点脚本化 → 80% 覆盖 |

## 小结

- 成本结构革命：-92%、五段 AI 替代率 70-95%、剩下的是判断
- 巴士测试 = 你不在场时业务能不能活；周末测试是最低门槛
- 单兵栈：Next/TS/Tailwind/Supabase/Vercel/Stripe，月 $20-50 起步
- 自动化布局原则：稀缺判断做该做，其他给系统
- 月度运营成本 ≤ MRR 30%；数字产品毛利率应 >80%
