# ch3 产品化

> 从"我有能力"到"我有可交付物"。产品化的本质是把一次性的人力，变成可重复销售的标准件。

## 这个阶段真正的问题

能力变现有一条默认的产品化阶梯，越往上可复制性越强、单次交付成本越低：

```
咨询/定制（卖时间，1:1）
  → 服务产品化（固定范围+固定价格的服务包，1:N 的雏形）
    → 数字产品（课程/模板/电子书，1:∞ 边际成本≈0）
      → 软件/SaaS（可自助订阅，1:∞ 且可自动交付）
```

**不要跳级**。直接做 SaaS 的问题：需求理解还没被服务阶段磨出来；从咨询起步的问题：卖时间是线性收入，天花板是你自己的日历。正确姿势是**用低层养活自己、用高层积累复利**，同一利基内逐级上移。

## MVP 的纪律

AI 时代 MVP 的中位节奏是 **2 周**（2026 中文访谈共识）。两周做不出来的 MVP 几乎都是范围问题，不是能力问题。MVP 的定义回到字面：**只保留收费所必需的最小功能集**。

一个有用的裁剪顺序：

1. 写下收费承诺（用户付钱买到什么结果）
2. 只做兑现这个承诺的功能
3. 其余全部进"付费后再说"清单——包括登录页美化、多语言、设置页……

取舍的优先级工具：MVP 阶段用 ICE 快筛就够（主观但快）；进入多需求排序后用 RICE；有明确时间窗口（季节性/竞品空窗）才值得上 WSJF。三套框架的共同已知局限：**都是"把争论变成数字"的沟通工具，不是优化器**——乘法制造伪精确，Impact 仍是主观量表，依赖项和大赌注被系统性压分（含 RICE 作者本人的声明）。

> 详细框架对比与局限清单见原[优先级与取舍框架]一章的合并内容；给自己的轻量三问：不做会怎样？最便宜的验证是什么？我在回避什么？

## 工程师的一人公司特殊优势

技术背景在这个阶段的三个杠杆：

1. **交付成本近零**：2026 年主流单兵栈已固化（Next.js + TS 全栈 / Tailwind + shadcn / Supabase / Vercel / Stripe），月度基础设施 $20-50
2. **自动化自己**：你的产品可以直接吃你自己的工作流——一人公司的产品往往从"我自己的重复劳动"长出来
3. **集成溢价**：垂直 Agent（如外贸 AI 回邮，客单 3000 元/月 × 300 客户）赢在懂业务集成，不在模型本身

对应的风险：工程师最容易在"做"里找安全感——把开发当避风港，回避销售和获客（ch5/ch6 才是多数人的真瓶颈）。

## 基准

| 指标 | 数字 | 口径 |
|---|---|---|
| MVP 开发周期（AI 辅助） | 2 周（中位），demo 25 分钟-2 天 | 中文访谈自报 |
| 单产品启动成本 | < $500（Marc Lou 多数产品） | 自报 |
| 基础设施月成本 | $20-50（工具订阅+托管） | 社区共识 |
| 免费→付费转化 | freemium 好 3-5%、优 8-12%；免费试用（要卡）约 30% | ChartMogul×ProductLed 2026，n=200 |

## 坑与证伪

| 坑 | 事实 |
|---|---|
| "功能够多才好卖" | 反例遍地：从大平台拆单点功能的"减法产品"活得很好（ch1）。卖的是结果，不是功能数量 |
| 一次只做一个产品最专注 | 两个流派都有证据：专注派（HeadshotPro）vs 组合派（Levels 7+、Marc Lou 21 个）。分界线是**单产品验证周期**——组合派的纪律是"每个都便宜地试"，不是"同时精细打磨" |
| 先做产品再想收费 | 收费方式决定产品形态（订阅要求持续价值、买断要求一次性价值交付）。ch4 和 ch3 应该同时想 |
