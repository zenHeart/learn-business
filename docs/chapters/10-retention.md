# 第 10 章 留存指标：从 NRR 到 RARRA 的诊断仪表盘

> **能力对应**：retention-metrics
> **学习目标**：能区分 NRR / GRR / Churn / DAU/MAU / RARRA 并搭建留存仪表盘与漏斗监控。

## 真实场景

一位创始人 DAU/MAU 看着稳定 30%，但他不知道 NRR（净收入留存）只有 85%——表面用户活跃，实际收入在流失。原因：他在看"用户活跃"而没看"付费留存"。结果融资时用 DAU/MAU 谈估值，被投资人用 NRR 戳穿。

## 为什么留存是 L2 的能力中枢

增长循环拉新用户，留存决定这些用户的"价值能否持续兑现"。没有留存，增长循环拉得越多亏得越多。L2 把留存作为中枢能力：定位错了留存差，定价错了留存差，循环错了留存差——所有上游错误都会在留存指标里反映出来。

## 第一节 五个核心留存指标

| 指标 | 公式 | 含义 |
|---|---|---|
| DAU/MAU | 日活 ÷ 月活 | 用户粘性 |
| NRR | (起始 ARR + 扩展 - 流失 - 降级) ÷ 起始 ARR | 收入粘性（含扩展） |
| GRR | (起始 ARR - 流失 - 降级) ÷ 起始 ARR | 收入粘性（不含扩展） |
| Logo Churn | 流失客户数 ÷ 起始客户数 | 客户粘性 |
| Revenue Churn | 流失收入 ÷ 起始收入 | 收入流失率 |

L2 默认：**SaaS 必须看 NRR 和 GRR 两者**，缺一会被误判。

## 第二节 NRR 的行业基准

| 业务类型 | 健康 NRR | 优秀 NRR |
|---|---|---|
| SMB SaaS | 100-110% | ≥ 120% |
| Mid-Market SaaS | 110-120% | ≥ 130% |
| Enterprise SaaS | 120-140% | ≥ 150% |
| 消费订阅 | 95-105% | ≥ 110% |

NRR > 100% 意味着不靠新客也能增长——这是 SaaS 估值溢价的核心来源。

L2 强调：**NRR 是投资人最看重的指标之一**，但前提是 NRR 数字真实。常见造假：把流失客户重签为新客户、把降级算扩展、把一次性服务费算入 ARR。

## 第三节 GRR 的硬约束

GRR（Gross Retention Rate）排除扩展收入，是真正的"留存率"。

```
GRR = 100% - 流失率 - 降级率
```

GRR 行业基准：

- SMB SaaS：≥ 85% 年化
- Mid-Market SaaS：≥ 90% 年化
- Enterprise SaaS：≥ 95% 年化

GRR < 80% 时，NRR 即使好看也撑不住——因为扩展客户也在流失。

## 第四节 Cohort 留存分析

Cohort（队列）分析是诊断留存的根本工具。

格式：横轴=注册后月数（0, 1, 2, ...），纵轴=队列（2024-01 注册、2024-02 注册...），每个格子=该队列在该月还活跃的用户比例。

```
        M0    M1    M2    M3    M4
2024-01 100%  60%   45%   38%   35%
2024-02 100%  62%   48%   40%   ...
2024-03 100%  58%   42%   ...
```

诊断要点：

- **M0 → M1 跌幅 > 30%**：onboarding 失败，新用户体验卡
- **持续下降但曲线趋平**：稳定留存，剩下的是核心用户
- **后期反升**：罕见，可能是有"激活期"或"承诺效应"
- **队列间下降加剧**：产品或市场在恶化

## 第五节 DAU/MAU 的边界

DAU/MAU 看似简单，常见误判：

- **不区分登录 vs 使用**：登录 ≠ 价值使用。DAU 应看"完成核心动作的用户数"。
- **不区分新老用户**：新用户的 DAU 会自然高于老用户，混在一起会掩盖流失。
- **不区分工作日 vs 周末**：B2B 工作日高、B2C 周末高，混在一起误判粘性。

正确用法：DAU/MAU 用于**横向比较自己**（本月 vs 上月），不用于**横向比较他人**（你的 DAU/MAU vs Slack 的 DAU/MAU 无意义——使用模式不同）。

## 第六节 RARRA 模型

AARRR 海盗指标是 Acquisition / Activation / Retention / Revenue / Referral；RARRA 是 Reforge 提出的逆向模型：

- **Retention**：用户是否回来（首要）
- **Activation**：用户是否体验到核心价值
- **Referral**：用户是否推荐
- **Revenue**：用户是否付费
- **Acquisition**：如何获取用户

L2 默认：**RARRA 把 Retention 放第一**——因为没有留存，其他环节都是空转。

## 第七节 留存仪表盘的最小集

L2 推荐每月看的 5 个指标：

1. **NRR**（净收入留存）— 趋势线
2. **GRR**（总收入留存）— 趋势线
3. **Logo Churn**（客户流失率）— 月度
4. **Cohort M3 留存** — 队列表
5. **核心动作完成率** — 关键行为漏斗

数据来源：

- NRR/GRR：订阅系统（Stripe/Recurly）
- Logo Churn：CRM（HubSpot/Salesforce）
- Cohort：数据仓库（BigQuery/Snowflake + Mode/Looker）

## 第八节 留存诊断的四类问题

留存变差时 L2 列四类诊断：

1. **Onboarding 问题**：新用户没体验到 Aha Moment
2. **产品问题**：用户开始用但价值衰减
3. **客户问题**：用户群体换了（新用户质量差）
4. **外部问题**：市场变化（竞品、政策）

诊断顺序：先看 Cohort M0-M1（onboarding），再看 M3-M6（产品），最后看新客结构（客户）。

## 常见证伪与坑

- **"DAU 高就好"**：错。DAU 高但 M1 留存低 = 用户来一次就走。
- **"NRR 高就健康"**：错。NRR 高但 GRR 低 = 扩展掩盖流失。
- **"留存公式可以套用"**：错。不同业务的最关键留存指标不同——SaaS 看 NRR、消费看 DAU/MAU、市场看供给方活跃。

## 验收标准

学完本章，你应能：

1. 算出你业务的 NRR、GRR、Logo Churn 并对标行业基准
2. 画一张 Cohort 表并诊断当前留存的瓶颈环节
3. 选定 1 个留存仪表盘指标作为本季度北极星
4. 给出至少 1 个留存改善假设 + 验证方法
