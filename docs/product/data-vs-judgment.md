# 数据 vs 判断力

> 工程师面对商业决策的典型代偿：不信任自己的判断，于是造一套系统（打分板、Rubric、检索证据）替自己背书。系统有价值，但判断力本身只能靠"决策 → 记录 → 复盘"长出来。

## 代偿的识别信号

以下措辞如果反复出现在你的工作里，说明判断力正在被系统代偿：

- "这不是拍脑袋排的"——优先级引用看板评分
- "不是凭感觉"——结论附上一堆检索证据
- 给**只有两个选项**的决策搭评分矩阵
- 用"再收集一点数据"推迟本可以当天拍板的决定

这些行为单独看都是好实践，问题出在**动机**：如果系统的角色是"替我背锅"而不是"让讨论显式化"，它就只是判断力的止痛药。

## 决策分型：哪些该等数据，哪些该直接判断

| 决策类型 | 特征 | 正确姿势 |
|---|---|---|
| **可逆 + 便宜** | 试错成本低，回滚容易 | 直接拍板，快速验证（这是判断力的练习场） |
| **可逆 + 贵** | 能回滚但浪费大 | 小成本先导实验，数据服务于实验设计 |
| **不可逆 + 便宜** | 错了也损失小 | 拍板，记录预期，事后复盘 |
| **不可逆 + 贵** | 战略级 | 数据 + 框架 + 多人挑战——但最终仍是一个人拍板并署名 |

关键认知：**最后一行也不是"数据决策"，只是"信息更充分的判断"**。框架和数据的作用是把假设显式化、把分歧摆上桌，不是消除判断本身。

## 判断力的训练闭环

```
决策 → 写下预期（3 个月后应看到什么）→ 到期对照 → 记录偏差原因
```

- 预期必须**事前**写：事后解释人人都是先知
- 偏差原因归到三类之一：**信息不足**（当时拿得到但没拿）/ **框架错误**（维度想岔了）/ **判断失误**（信息框架都对，选错了）
- 只有第三类是真正的判断力训练素材；前两类改进的是流程不是判断

## 已知局限

- "跟着直觉走"同样是被神化的叙事：直觉是内化的模式识别，**只在有充分同类经验积累的领域可靠**（来源：Kahneman《思考，快与慢》对专家直觉适用条件的论述——环境规律性 + 反馈质量）
- 数据驱动在指标代理不当时会系统性跑偏（古德哈特定律：指标一旦成为考核目标就被博弈）
- 小样本场景（团队一年做不了几次战略决策）下，复盘闭环比"多决策"更重要

## 给自己的锚点

- 建立一个"决策日志"：每条记录 = 日期 / 决策 / 预期 / 到期日
- 下次想说"这不是拍脑袋"时，改成把**反方最强论点**写出来——能写出反论点的判断才值得署名
- 季度复盘：翻决策日志，统计三类偏差的占比

## 来源

- 判断分型参考 Amazon "Type 1 / Type 2 decisions"（Bezos 致股东信，单向门 vs 双向门）
- 直觉适用条件：Daniel Kahneman《思考，快与慢》
- 古德哈特定律：Goodhart《Problems of Monetary Management》及后续学界共识表述
