# ch11 一人公司的数据挖掘

> **本章目标**：建立一人公司完整的数据思维——从"事件→指标→报表→洞察→行动"的闭环；掌握核心指标的计算与解读（漏斗、单位经济、留存）；建立"护栏指标"防止主指标被做坏；用 GA4/PostHog 等工具做基础分析。这是把"感觉"换成"判断"的章节。

## 真实场景

两位独立开发者都做"在线协作文档"产品。A 觉得产品做得不错但"转化差"，于是改落地页（ch10）改了三版还是不行。B 把"转化差"拆开看：免费→试用转化 4%（行业基准 8%，偏低）→ 试用→付费 25%（健康）→ 30 日留存 12%（健康）→ 90 日留存 4%（**问题在这**：90 日几乎都流失）。B 改的不是转化页——是 90 日的"留存失败"信号。**数据挖掘的第一步是把"一个症状"拆成"哪个环节的指标异常"。**

## 数据四步：事件→指标→报表→行动

```
① 事件埋点：用户在产品里做了什么（点击、付费、退出、邀请）
② 指标计算：事件聚合成数字（PV/UV/转化率/留存率/ARPU/LTV）
③ 报表呈现：周期性看这些数字（周报/月报/实时）
④ 行动：报表里的异常 → 假设 → 验证 → 落地
```

一人公司常见错误：**只做了 ①②（埋点+看数），没有 ④**。每周看报表，发现异常，然后……继续看。这是数据惰性。每个异常必须落地到"接下来 7 天做什么"。

## 核心指标体系

按一人公司的复杂度，从外到内六层（每层对应一个**问题**）：

```
第 1 层 流量    —— 多少人来？（PV/UV/渠道分布）
第 2 层 漏斗    —— 多少人留下？（访问→注册→试用→付费）
第 3 层 留存    —— 留下来的人用多久？（D1/D7/D30/D90 留存率）
第 4 层 单位经济 —— 一个人贡献多少、消耗多少？（ARPU/LTV/CAC）
第 5 层 增长    —— 老用户带不带新用户？（K 因子/推荐率/病毒系数）
第 6 层 财务    —— 整盘能不能算清账？（毛利率/月净利润/现金流）
```

**新项目只盯第 1-3 层**；**成熟项目才把第 4-6 层当主菜**。反过来也是常错位：0 收入时算 LTV 是数字游戏。

### 关键公式

| 指标 | 公式 | 健康参考 |
|---|---|---|
| 激活率 | 注册→完成核心动作的 % | 看行业基准（ch10） |
| 留存率 D7 | 第 7 天回访 % | 工具/内容类 20-40%，社交/通讯 50%+ |
| 留存率 D30 | 第 30 天回访 % | 比 D7 更能反映长期价值 |
| ARPU | 总收入 ÷ 付费用户数 | 看 ch07 三档加权后 |
| LTV | ARPU × 订阅时长（或 ARPU ÷ 月流失率） | 与 CAC 比较（>3 健康） |
| CAC | 获客总支出 ÷ 新增付费用户 | 渠道敏感，独立看每个渠道的 |
| LTV/CAC | 长期利润的根 | **>3 健康**，<1 烧钱 |
| 毛利率 | （收入 − 边际成本）÷ 收入 | 数字产品应 >80% |

## 留存：一人公司的生死线

之所以单独提留存：被反复引用的"独立产品 MRR 中位 $145-500、$10k 比例 3-6%"——核心瓶颈不是获客，是**留不住**。有用户来了用了一次就再也不回来，转化率再高也没用。

**留住用户的本质 = 用户的下一个动作比上一次有价值**。这要求产品对用户的"价值兑现节奏"是连续的：每天打开有价值、每周用有新功能、每月有惊喜——任选其一。

留存诊断（必备四件套）：

1. **同期群留存曲线**（cohort retention）：按注册周分群，看每群第 N 周的回访率。健康形态：陡降后趋平（horizontal），"刀片式"短平快；如果曲线持续陡降=产品没让人形成习惯
2. **功能使用深度**：用户平均用了几次核心功能（按分位数看，p50 用了 X 次，p10 用了 Y 次——p10 的人往往就是流失候选）
3. **流失节点**：用户最后一次做了什么动作离开的（ch12 的"巴士测试"反面）
4. **唤醒实验**：流失用户用邮件/通知能唤回多少%——这是留存弹性的真值

## 护栏指标：防主指标被做坏

经典反例：某增长团队把"日活"当主指标，奖励刷日活的产品行为（弹窗轰炸、推送疲劳），DAU 涨了但用户悄悄走光了——只是走之前被多打搅了几次。**主指标被博弈 = 数据系统性的坏**（古德哈特定律：一旦被考核就被博弈）。

护栏设计：每个主指标配 1-2 个反向护栏。

| 主指标 | 护栏 |
|---|---|
| 日活 | 7 日回访率（确认不是一次性的假活） |
| 转化率 | 退款率（确认不是被坑进来的） |
| 留 7 日 | 投诉率 / 反馈负面情绪 |
| MRR | 退款 + 流失率（确认不是低价高流的） |
| NPS | 客户流失率（推荐意愿是因，流失是果） |

每个数字升了都在合理范围内，**才**算真改进。

## 一人公司最常用分析工具

按 2026 的事实标准（开源优先、低学习成本）：

- **PostHog**（推荐）：开源产品分析 + 录屏 + Feature Flag + 评测，覆盖 ④ 全栈；自托管免费、托管有免费层
- **Plausible / Umami**：轻量网站分析（替代 GA4），隐私友好
- **GA4**：免费但学习成本与功能复杂度都更高
- **Stripe Dashboard**：订阅/退订/退款/分账的财务数据
- **Notion / 飞书表格 + 定时导出 SQL 数据**：留作自定义报表

最低配置：PostHog + Stripe Dashboard + 每周自填的"产品改动→指标变化"日志。后者尤其重要——没有它你只能看到结果看不到原因。

## 数据驱动决策的纪律

**不要让数据替你做决定**——数据是诊断工具，不是决定器。决策永远是你的，但要被数据**校准**。

四种使用方式：

1. **校验（Validate）**：改完一段文案/一个功能，盯着关键指标——是预期方向吗？（注意小流量的统计显著问题：<1000 转化/日的差异基本是噪声）
2. **定位（Locate）**：现象→拆解→找到异常环节（开头 B 同学的 90 日留存拆解）
3. **警醒（Alert）**：护栏指标的突变 = 系统问题信号
4. **破除错觉（Dispel）**：你相信了 6 个月的"用户爱用 XX"——数据可能显示用 XX 的人 7 日后 90% 流失。**情绪的偏好不是用户的偏好**（ch00 的代偿信号）

## 基准数据（再次校准）

| 指标 | 数字 | 口径 |
|---|---|---|
| 独立产品 MRR 中位 | $145-500 | IH Stripe 核验样本，**有收入样本**（非全员） |
| $10k MRR 比例 | 3-6% | 同上 |
| 工具类 D7 留存 | 20-40% | 行业经验 |
| SaaS 健康 LTV/CAC | >3 | 行业基准 |

## 坑与证伪

| 坑 | 核查 |
|---|---|
| 指标越多越好 | 5 个核心指标能看懂的才看。指标墙是分析者的遮羞布 |
| 看周报就完事 | 周报是事后看护栏。实时数据用于"今天发生了什么"——**没实时 dashboard 也能活，没周报不能活** |
| 自报数据可改 | **Stripe 核验过的 Stripe 数据 > 任何自报**。能调第三方核验就用第三方 |
| "DAU 涨了就是好事" | 主指标增长必须配护栏稳定——单日数据波动 30% 都不罕见，单点不长期趋势不变都是噪声 |
| 把"昨天转化高"当结论 | 至少看 4 周趋势；样本量决定统计显著（ch10 落地页） |

## 小结

- 数据四步：事件→指标→报表→行动，**没有④等于没做**
- 指标六层：流量/漏斗/留存/单位经济/增长/财务；新项目盯前 3 层
- 留存是生死线：同期群曲线 + 功能深度 + 流失节点 + 唤醒实验
- 护栏指标防主指标被博弈（古德哈特定律）
- 数据校准你的决定，不替你做决定
