# ch7 交付与自动化

> 一人公司的产能公式：你不再是执行者，你是**决策者 + 自动化系统的维护者**。交付阶段的全部工程问题是——把"只有你能做的判断"和"谁都能做的执行"分开，后者全部外包给 AI/工具/脚本。

## 成本结构的革命

2026 年被反复引用的对比（口径与来源见附录）：

| 项目 | 传统团队 | 一人 + AI | 降幅 |
|---|---|---|---|
| 年人力/运营成本 | ~$22.5 万（5-15 人团队） | ~$1.8 万 | **-92%** |
| 开发 | 5 人技术团队 | 1 人 + AI Coding | -80% |
| 设计 | 全职设计师 | 1 人 + AI 生图 | -90% |
| 内容 | 3 人团队 | 1 人 + LLM | -85% |
| 客服 | 5 人团队 | Agent 机器人 | -95% |

真实创业者自报的 AI 承担比例：美术 70%（弹幕游戏链路：豆包→Banana→Triple3D→Blender→Mixamo）、重复性工作 80%（DeepSeek/Claude Agent）、跨境电商运营 60%。**剩下的 20-30% 是判断、框架设计与客户沟通**——这正是 ch1 说的行业认知所在。

## 一人的标准工具栈

被 2026 年独立开发者社区固化的组合（月成本 $20-50 起）：

```
开发：Next.js + TypeScript（全栈统一）
UI：Tailwind + shadcn/ui
数据：Supabase（自带免费额度的 Postgres+Auth）
部署：Vercel
收款：Stripe（海外）/ 微信支付宝（国内）
AI：Cursor / Claude Code / 豆包 / DeepSeek（按需）
```

选择原则不是"最好"，是**最短路径 + 最低维护**。一人公司每引入一个自运维组件（自建数据库、K8s），都在透支未来自己的时间。

## 巴士测试：自动化的验收标准

Levels 在 MAKE 里的标准：**你被公交车撞了，产品还能正常运行多久？**

- 收入型业务至少要过"周末测试"（两天不管不崩）
- 逐项排查：付款→交付（ch6 的自动闭环）、常见问题自助（FAQ/机器人）、故障时的降级路径、月度账单自动对账
- 过不了巴士测试的业务 = 你买了一份不能请假的工作，不是资产（对照 ch8 的资产定义）

## 什么不自动化

- **客户关系的关键时刻**：首单欢迎、流失挽回、大客户投诉——AI 起草，你签名
- **产品方向决策**：数据回收可以自动化，"下一版做什么"不能（ch9）
- **内容的人格部分**：AI 可以量产平庸内容，但受众跟随的是你（ch5 的信任来源）——AI 辅助生产，不代替署名判断
- 质量红线场景：中文访谈的原话——"需要实时监控 Agent 的工作进度与产出方向，防止偏离目标"

## 坑与证伪

| 坑 | 事实 |
|---|---|
| 全自动躺赚 | "被动收入"叙事被数据反复打脸：MRR 中位 $145-500 的现实里，自动化降低的是交付成本，获客与信任没有被动版 |
| 工具链越全越好 | 每个工具都是新的失效点和订阅成本。判断标准：这个工具替代的工时 > 维护它的工时才引入 |
| 把 AI 当技术合伙人 | AI 是执行放大器：放大正确判断，也放大错误判断。行业老手用 AI 是杠杆，新手用 AI 是加速犯错——差异在纠错能力（ch1） |
| 自动化一次到位 | 先手动跑通全流程（哪怕用表格+日历），再逐段替换。没跑过的流程没有自动化资格 |
